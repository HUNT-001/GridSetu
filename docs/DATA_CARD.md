# Data card

Where every input to GridSetu comes from, how it was checked, and what it may and may not
be used for. Four labels:

- **REAL:** measured or published data, used as published.
- **DERIVED:** computed from real data by a stated method.
- **SOURCED:** a parameter taken from a named specification or datasheet, not measured on our feeder.
- **SYNTHETIC:** generated by the simulator or set by us as an engineering assumption.

The headline results (README "Results", `outputs/numbers.json`) run on the synthetic scenario.
The real data is used to test that scenario (`python -m gridsetu real-data`) and can replace
the synthetic weather and prices through two switches in `config/city.yaml`:

```yaml
simulation:
  weather_source: synthetic     # or nasa_power
exchange_price:
  source: synthetic             # or iex
```

The simulated week (14–20 Sep 2026) maps to the same calendar dates in 2025. Its eight
training weeks then start on 20 Jul 2025, the first day of the weather file.

## Real data

### Weather: NASA POWER, Coimbatore (REAL)

| | |
|---|---|
| File | `data/real/nasa_power_coimbatore_2025.csv` |
| Source | NASA Langley Research Center POWER project, hourly point API v2.10.5 (MERRA-2 reanalysis, CERES SYN1deg). The exact request URL is in the file header. |
| Location | lat 11.02, lon 76.96 (Coimbatore) |
| Period | 20 Jul 2025 00:00 to 21 Sep 2025 23:00, 1,536 hours |
| Fields | all-sky GHI, clear-sky GHI (W/m², hourly mean), 2 m air temperature (°C) |
| Retrieved | 23 Nov 2026 |
| Check | All 1,536 rows were compared with sums computed on the API response: all-sky GHI total 264,840, clear-sky 435,132, temperature × 100 total 3,716,147, and each of the 64 daily sums. All match. |
| Licence | NASA POWER data is free to use with acknowledgement of the POWER project. |

**Time zone.** NASA labels the hours "LST", which here is UTC+5. Indian time is UTC+5:30, so
IST = LST + 30 minutes. We checked this against solar geometry: our clear-sky model matches
NASA's clear-sky column best at +30 minutes (correlation 0.997; 0.985 at 0 minutes). A test
re-checks this.

### Exchange prices: IEX day-ahead market (REAL)

| | |
|---|---|
| File | `data/real/iex_dam_2025-09-14_20.csv` |
| Source | Indian Energy Exchange, Day-Ahead Market, Market Snapshot, 15-minute blocks (iexindia.com). |
| Period | 14–20 Sep 2025, 7 days × 96 blocks = 672 rows |
| Fields | purchase bid, sell bid, MCV, final scheduled volume (MW), market clearing price MCP (₹/MWh, all-India, unconstrained) |
| Retrieved | 23 Nov 2026, from the public page, read programmatically from the page text (no retyping) |
| Check | For each day, the mean of the 96 MCP values equals IEX's own published daily average to within ₹0.005/MWh. A test re-checks all 7 days. |
| Terms | IEX: "Only correct quotation with attribution is permitted." Cite IEX whenever these prices are shown. |

**What it is not.** The MCP is the all-India unconstrained price. It is not the Tamil Nadu
(S2) area price and not a retail tariff. The ₹10,000/MWh values are the exchange's price
ceiling, so the true scarcity value in those blocks was at least that.

## Derived data

| Item | Method | Effect |
|---|---|---|
| 15-minute GHI from hourly NASA values | Each hour's NASA energy is spread over its four steps in proportion to our clear-sky curve. Every hour keeps exactly NASA's energy (tested). | No cloud variability within an hour. This makes solar easier to forecast than reality, so solar-forecast scores on real weather flatter us. |
| 15-minute temperature | Linear between NASA hour midpoints | Negligible |
| Day-ahead weather forecast on real data | Persistence: tomorrow's sky = today's daily clear-sky index; tomorrow's temperature = today's at the same time. No archive of real weather forecasts was used. | Pessimistic: a numerical weather forecast would do better. |
| The first half hour (20 Jul, 00:00–00:30 IST) | Takes the first NASA hour's values (night) | None |

## Sourced parameters

These come from documents, not from our feeder. Details and links are in
`matlab/f07_params.json`.

| Parameter | Source |
|---|---|
| 315 kVA distribution transformer: impedance 4.5%, losses 1,025 W at 50% load and 3,100 W at 100% | WBSEDCL specification to IS 1180 (Part 1) Energy Efficiency Level 2 |
| ACSR Rabbit conductor resistance 0.5426 Ω/km at 20 °C | Apar Industries ACSR datasheet |
| Transformer thermal model and ageing law | IEC 60076-7. Distribution-transformer default constants are used and marked as still to be confirmed against the standard. |
| ₹10/kWh exchange price ceiling | IEX day-ahead market rules (confirmed in the IEX data above) |

## Synthetic

| Input | Where | Tested against real data? |
|---|---|---|
| Weather for the headline results | `src/gridsetu/weather.py` | Yes. Real sunshine was lower (4.1 vs 5.2 kWh/m²/day over the same 63 days) and steadier. |
| Exchange price curve for the headline results | `exchange_price` in `config/city.yaml` | Yes. The real evening reached the ₹10 ceiling on 6 of 7 days; ours stops at ₹9.8. Real midday prices were far lower. |
| Household, enterprise and critical loads; Tier 1/2/3 split; temperature sensitivity | `config/city.yaml`, `src/gridsetu/profiles.py` | No. The biggest remaining gap: no smart-meter data yet. |
| Wind generation | `src/gridsetu/weather.py` (also used in real-weather runs) | No |
| City generation fleet, network, forced outage | `config/city.yaml` | No |
| DISCOM relief requests and rotation | `config/city.yaml`, `src/gridsetu/market.py` | No |
| Communications loss | `comm_slices` in `config/city.yaml` | No |
| Low-voltage network layout (lengths, buses, power factor, ±6% limit) | `matlab/f07_params.json` | No; to be checked with a DISCOM engineer |
| Household responses (overrides, fairness) | `src/gridsetu/fairness.py` | No |

## Use and limits

- Say "simulation" whenever a headline figure is shown. Say "real weather" or "real IEX
  prices" only for the `real-data` results, and add that household load is synthetic.
- The real data covers one stress week and its training weeks. It cannot yet support a
  monthly figure on real weather.
- Adding data: put the file in `data/real/` with a header giving the source, URL, date
  retrieved and units; add a check that compares it with a published total; list it here.
